# macOS Electron API Coverage

Updated: 2026-06-26

This matrix tracks Electron-like API coverage that is backed by macOS code and regression tests. It is intentionally scoped to APIs that are either implemented or are the next practical compatibility targets.

| Module / API | Windows behavior in this tree | macOS implementation | E2E coverage | Gap / next step |
| --- | --- | --- | --- | --- |
| BrowserWindow lifecycle | Win32 HWND create/show/hide/minimize/maximize/focus/close flow | `mac_window` plus Win32-compatible HWND shims | Yes, `browserwindow-*` checks | Add app-level quit/window-all-closed semantics |
| WebContents navigation | Load URL/file, history, stop, title/url/load callbacks | miniblink callbacks and mac host window | Yes, navigation/load/script/source checks | Keep expanding Electron callback parity |
| Session storage/cookies | Cookie API, localStorage/sessionStorage partition behavior | Cookie jar/path shims and per-view storage paths | Yes, session partition checks | Add more session permission/cache APIs |
| webRequest | begin/end, redirect, cancel, post body | miniblink load URL callbacks | Yes, `session-webrequest-*` | Add auth/proxy/header edge cases |
| Dialog | MessageBox, open/save file, open directory | Deterministic Win32-compatible shim | Yes, `dialog-*` | Optional real `NSOpenPanel`/`NSSavePanel` behind non-CI path |
| Menu/context menu | Create/append/insert/state/track/system menu | In-process menu model plus command dispatch | Yes, `menu-*` | Add accelerator and richer role behavior |
| Tray | `Shell_NotifyIcon` add/modify/delete/version/focus | In-memory status item model | Yes, `tray-*` | Add native status item rendering/events |
| NativeImage/bitmap | DIB section, masks, memory DC, clipboard DIB, icon lifecycle | GDI-compatible bitmap/DC/icon shims | Yes, `nativeimage-*` | Add more image decode/scale variants |
| Shell openPath/openExternal | `ShellExecuteW` and `ShellExecuteExW` | `/usr/bin/open`, quoted URL cleanup, deterministic E2E log hook | Yes, `shell-open-*` plus `shell-js-smoke` | Add async native error-string parity for `openPath` if modern Electron semantics are required |
| Shell showItemInFolder | `SHOpenFolderAndSelectItems` optional path with `ShellExecuteExW` fallback | Direct PIDL reveal API plus fallback-compatible shell32 probing | Yes, `shell-show-item-*` plus `shell-js-smoke` | Replace fallback with direct platform_util path when COM branch is removed |
| Shell trashItem | Move item to Recycle Bin through shell file operation | `SHFileOperationW(FO_DELETE | FOF_ALLOWUNDO)` moves to `~/.Trash`; JS `trashItem()` Promise wraps legacy `moveItemToTrash()` | Yes, `shell-trash-item-*` plus `shell-js-smoke` | Add multi-item and directory trash cases |
| Shell beep | `MessageBeep(MB_OK)` | `MessageBeep`/`Beep` shim with test suppress switch | Yes, `shell-beep-*` plus `shell-js-smoke` | Optional native sound API if needed |
| App path/locale | SHGetFolderPath, known folder, temp path, locale APIs used by Electron app | macOS folder mapping, known Downloads/temp folders, dynamic locale shim; `ApiApp::getPath()` now honors `setPath()` overrides | Yes, `app-path-*` including temp plus `app-locale-*`, `app-js-smoke`, and stubbed `app-runtime-js-smoke` | Add native Electron-mode binding smoke once `mac_release_arm64` enables Electron mode |
| App name/version | Electron app metadata setters/getters | Existing C++ fields in `ApiApp` | Yes, `app-js-smoke` | Add native Electron-mode binding smoke when runtime path is enabled |
| App lifecycle | quit, before-quit, window-all-closed | `app.quit()` emits `before-quit`, then closes windows and posts `WM_QUIT`; `app.exit()` remains immediate exit; window-all-closed hook exists in `ApiBrowserWindow` | Partial, `app-lifecycle-*` covers Win32 message-loop quit path; `app-js-smoke` and stubbed `app-runtime-js-smoke` cover JS event order | Add native Electron-mode event-order smoke for `before-quit/window-all-closed` |
| Single instance lock | Process-level named mutex | Win32-compatible named mutex shim; `requestSingleInstanceLock()` tracks the lock handle and existing release entry closes it | Yes, `app-single-instance-mutex`, `app-js-smoke`, and stubbed `app-runtime-js-smoke` | Add cross-process callback/argv forwarding case |
| globalShortcut | Register/unregister accelerators and receive `WM_HOTKEY` callbacks | Win32-compatible `RegisterHotKey`/`UnregisterHotKey` now registers macOS process-wide Carbon `EventHotKey` handles, keeps duplicate/id checks, posts `WM_HOTKEY`, and releases OS handles on unregister/window destroy; JS API preserves accelerator normalization and the native hook surface | Partial, `global-shortcut-*` covers registration conflicts, OS hotkey handle presence, unregister, hotkey message format, and destroy cleanup; `global-shortcut-js-smoke` covers JS state and hook behavior | Wire the macOS backend into a formal Electron `globalShortcut` native binding/runtime path |
| screen | Display list/primary display/cursor point plus `MonitorFromPoint/Rect` default semantics | NSScreen-backed Win32 monitor metrics, point/window/rect monitor lookup, monitor info, display enumeration, cursor point; Electron common screen binding now maps `getDisplayNearestPoint`/`getDisplayMatching` through cached display bounds instead of primary-display stubs; mac `libelectron.a` includes `_register_electron_common_screen`, and the Electron-mode executable registers the binding through `nodeModuleInitRegister()` | Yes, `screen-*` covers monitor metrics/enumeration/lookup, `MonitorFromRect`, nearest/default fallback, and clipped-empty enumeration; `screen-js-smoke` covers JS export shape and method delegation; `run_electron_mode_smoke.sh` checks screen linked-binding registration; cursor point already used by menu/input paths | Add native Electron-mode runtime E2E after full Node `process._linkedBinding` initialization is wired |
| nativeTheme | Theme/dark mode/high contrast | `SystemParametersInfoW` supports work area, animation, deterministic high contrast; JS `nativeTheme` exposes themeSource/read-only state, macOS system dark-mode detection, and prefers `electron_browser_native_theme` OS notification over fallback polling; Electron-mode binding source uses AppKit `effectiveAppearance` KVO; mac `libelectron.a` builds a minimal linked-binding archive containing `_register_electron_browser_native_theme`; mac `libnodejs.a` now supplies the minimal linked-binding bridge and `nodeModuleInitRegister()` for this binding; `blink_build.js ... electron` pulls the nativeTheme registration object into the Electron-mode executable | Partial, `native-theme-*` covers deterministic native queries; `native-theme-js-smoke` covers JS export shape, themeSource, system dark-mode override, fallback watcher updates, high contrast, and systemPreferences proxy; `native-theme-native-notification-smoke` covers the no-polling native binding path with a mocked binding; `electron_build.js mac_release_arm64`, `node_build.js mac_release_arm64`, and `blink_build.js mac_release_arm64 ... electron` verify archive/executable symbol availability | Add native Electron-mode binding E2E after the mac executable is switched to a real Electron entry point and full Node runtime/environment initialization is wired |
| powerMonitor | Suspend/resume/power events plus idle/battery state queries | Deterministic `GetSystemPowerStatus` shim for AC/battery status now uses macOS power-source data by default; idle APIs use existing Chromium path; macOS IOKit sleep/wake and power-source notifications are bridged into `WM_POWERBROADCAST`; `ApiPowerMonitor` creates a message window and registers the native bridge; mac `libelectron.a` includes `_register_electron_browser_powermonitor`, and the Electron-mode executable registers the binding through `nodeModuleInitRegister()` | Partial, `power-monitor-system-power-status-*` covers power status query; `power-monitor-native-notification-bridge` covers native notification dispatch into `WM_POWERBROADCAST`; `power-monitor-js-smoke` covers JS idle APIs, battery query, and suspend/resume/on-ac/on-battery/shutdown event shape; `run_electron_mode_smoke.sh` checks powerMonitor linked-binding registration | Add native Electron-mode event-order smoke after full Node `process._linkedBinding` runtime initialization is wired |
| powerSaveBlocker | `start(type)`, `stop(id)`, `isStarted(id)` plus Win32 execution-state blocker semantics | JS blocker lifecycle aggregates to native `electron_browser_power_save_blocker.setExecutionState()`; that binding delegates to `SetThreadExecutionState`, which is backed by macOS IOPM assertions; mac `libelectron.a` includes `_register_electron_browser_power_save_blocker`, and the Electron-mode executable registers the binding through `nodeModuleInitRegister()` | Partial, `power-save-blocker-js-smoke` covers the formal linked-binding lookup name plus ID/type behavior and native state transitions; `power-save-blocker-*` covers execution-state plus IOPM assertion behavior; `run_electron_mode_smoke.sh` checks powerSaveBlocker linked-binding registration | Add native Electron-mode runtime E2E after full Node `process._linkedBinding` initialization is wired |
