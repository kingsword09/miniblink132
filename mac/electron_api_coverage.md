# macOS Electron API Coverage

Updated: 2026-06-29

This matrix tracks Electron-like API coverage that is backed by macOS code and regression tests. It is intentionally scoped to APIs that are either implemented or are the next practical compatibility targets.

| Module / API | Windows behavior in this tree | macOS implementation | E2E coverage | Gap / next step |
| --- | --- | --- | --- | --- |
| BrowserWindow lifecycle | Win32 HWND create/show/hide/minimize/maximize/focus/close flow | `mac_window` plus Win32-compatible HWND shims; app-level close-all now propagates `WindowCloseCancelled()` to `app.quit()`; mac Electron-mode registers `electron_browser_browserwindow`, exports `BrowserWindow`, and routes the JS wrapper through the formal linked binding | Yes, `browserwindow-*` checks, Electron-mode `WindowList` close-all cancellation smoke, linked-binding runtime smoke, and `browser-window-webcontents-js-smoke` for constructor/static export/webContents proxy paths | Expand JS coverage for less-common window APIs as callers require them |
| WebContents navigation | Load URL/file, history, stop, title/url/load callbacks | miniblink callbacks and mac host window; mac Electron-mode registers `electron_browser_web_contents`, exports `webContents`, and dispatches renderer IPC through the shared public `ipcMain` JS module; `electron_browser_session`, `electron_browser_webrequest`, and `electron_browser_downloaditem` are registered before `webContents` construction | Yes, navigation/load/script/source checks plus `browser-window-webcontents-js-smoke` for loadURL/loadFile/send/insertCSS/static lookup wrapper paths | Keep expanding Electron callback parity |
| Session storage/cookies | Cookie API, localStorage/sessionStorage partition behavior | Cookie jar/path shims, per-view storage paths, public `session.defaultSession` / `session.fromPartition()`, preload list setters, download path, and permission handler registration storage | Yes, session partition checks plus `session-js-smoke` for export shape, default/fromPartition, preloads, permission handler registration, webRequest callback registration, and DownloadItem EventEmitter/cancel paths | Add real permission event dispatch and more cache APIs when miniblink exposes those hooks |
| webRequest | begin/end, redirect, cancel, post body | miniblink load URL callbacks; public `session.webRequest` registers all current callback slots through the formal native binding | Yes, `session-webrequest-*` plus `session-js-smoke` callback registration coverage | Add auth/proxy/header edge cases |

| net | Electron-like `net.request()` and online state surface | JS-only browser API backed by Node `http`/`https` plus `app.isOnline()`; string URL protocol parsing is corrected, `session` is sanitized before delegating to Node request objects, and request/header/write/end/abort/followRedirect proxy methods are covered | Yes, `app-runtime-js-smoke` checks public export shape and `net-js-smoke` covers online getter, http/https protocol selection, session sanitization, headers, event registration, write/end, redirect follow-through, and abort | Add Electron session-backed networking only if native session integration is required |
