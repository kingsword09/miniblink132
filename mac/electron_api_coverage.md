# macOS Electron API Coverage

Updated: 2026-06-27

This matrix tracks Electron-like API coverage that is backed by macOS code and regression tests. It is intentionally scoped to APIs that are either implemented or are the next practical compatibility targets.

| Module / API | Windows behavior in this tree | macOS implementation | E2E coverage | Gap / next step |
| --- | --- | --- | --- | --- |
| BrowserWindow lifecycle | Win32 HWND create/show/hide/minimize/maximize/focus/close flow | `mac_window` plus Win32-compatible HWND shims | Yes, `browserwindow-*` checks | Add app-level quit/window-all-closed semantics |
| WebContents navigation | Load URL/file, history, stop, title/url/load callbacks | miniblink callbacks and mac host window | Yes, navigation/load/script/source checks | Keep expanding Electron callback parity |
| Session storage/cookies | Cookie API, localStorage/sessionStorage partition behavior | Cookie jar/path shims and per-view storage paths | Yes, session partition checks | Add more session permission/cache APIs |
| webRequest | begin/end, redirect, cancel, post body | miniblink load URL callbacks | Yes, `session-webrequest-*` | Add auth/proxy/header edge cases |
| Dialog | MessageBox, open/save file, open directory | Deterministic Win32-compatible shim | Yes, `dialog-*` | Optional real `NSOpenPanel`/`NSSavePanel` behind non-CI path |
| Menu/context menu | Create/append/insert/state/track/system menu | In-process menu model plus command dispatch | Yes, `menu-*` | Add accelerator and richer role behavior |
| Tray | `Shell_NotifyIcon` add/modify/delete/version/focus | In-memory status item model | Yes, `tray-*` | Add native status item rendering/events |
| NativeImage/bitmap | DIB section, masks, memory DC, clipboard DIB, icon lifecycle | GDI-compatible bitmap/DC/icon shims | Yes, `nativeimage-*` | Add more image decode/scale variants |
| Shell openPath/openExternal | `ShellExecuteW` and `ShellExecuteExW` | `/usr/bin/open`, quoted URL cleanup, deterministic E2E log hook; JS `openPath()` now returns `Promise<string>` and maps legacy native bool/exception results to Electron-style error strings | Yes, `shell-open-*` plus `shell-js-smoke` including async `openPath` success/error-string cases | Add native `/usr/bin/open` exit-status detail if callers need OS-specific error text |
| Shell showItemInFolder | `SHOpenFolderAndSelectItems` optional path with `ShellExecuteExW` fallback | Direct PIDL reveal API plus fallback-compatible shell32 probing | Yes, `shell-show-item-*` plus `shell-js-smoke` | Replace fallback with direct platform_util path when COM branch is removed |
| Shell trashItem | Move item to Recycle Bin through shell file operation | `SHFileOperationW(FO_DELETE | FOF_ALLOWUNDO)` moves files/directories to `~/.Trash`; JS `trashItem()` Promise wraps legacy `moveItemToTrash()` | Yes, `shell-trash-item-*` covers single-file, multi-file, and directory cases plus `shell-js-smoke` | Add collision/error-detail cases if needed |
| Shell beep | `MessageBeep(MB_OK)` | `MessageBeep`/`Beep` shim with test suppress switch | Yes, `shell-beep-*` plus `shell-js-smoke` | Optional native sound API if needed |
| App path/locale | SHGetFolderPath, known folder, temp path, locale APIs used by Electron app | macOS folder mapping, known Downloads/temp folders, dynamic locale shim; `ApiApp::getPath()` now honors `setPath()` overrides | Yes, `app-path-*` including temp plus `app-locale-*`, `app-js-smoke`, and stubbed `app-runtime-js-smoke` | Add native Electron-mode binding smoke once `mac_release_arm64` enables Electron mode |
| App name/version | Electron app metadata setters/getters | Existing C++ fields in `ApiApp` | Yes, `app-js-smoke` | Add native Electron-mode binding smoke when runtime path is enabled |
| App lifecycle | quit, before-quit, window-all-closed | `app.quit()` emits `before-quit`, then closes windows and posts `WM_QUIT`; `app.exit()` remains immediate exit; window-all-closed hook exists in `ApiBrowserWindow` | Yes, `app-lifecycle-*`, `app-js-smoke`, and `electron-app-smoke` cover Electron-mode event order plus `app.exit()` behavior | Add richer BrowserWindow-backed quit cancellation cases |
| Single instance lock | Process-level named mutex plus second-instance forwarding | Win32-compatible named mutex shim; mac Electron-mode path uses lock file plus AF_UNIX socket forwarding for argv/cwd callbacks; `requestSingleInstanceLock()` tracks and releases the lock | Yes, `app-single-instance-mutex`, `app-js-smoke`, and `electron-app-single-instance-smoke` cover cross-process argv/cwd forwarding | Add stale socket crash-recovery stress if needed |
| globalShortcut | Register/unregister accelerators and receive `WM_HOTKEY` callbacks | Win32-compatible `RegisterHotKey`/`UnregisterHotKey` now registers macOS process-wide Carbon `EventHotKey` handles, keeps duplicate/id checks, posts `WM_HOTKEY`, and releases OS handles on unregister/window destroy; JS API preserves accelerator normalization and now prefers the formal `electron_browser_global_shortcut` linked binding, which owns a hidden message window and dispatches `WM_HOTKEY` to JS callbacks; mac `libelectron.a` includes `_register_electron_browser_global_shortcut`, and the Electron-mode executable registers the binding through `nodeModuleInitRegister()` | Partial, `global-shortcut-*` covers registration conflicts, OS hotkey handle presence, unregister, hotkey message format, and destroy cleanup; `global-shortcut-js-smoke` covers JS state plus the formal linked-binding lookup name/fallback behavior; `run_electron_mode_smoke.sh` checks linked-binding registration, controlled V8 runtime lookup/export availability, and real Node bootstrap `process._linkedBinding(...)` access | Add interactive accelerator dispatch E2E outside CI-safe smoke |
| screen | Display list/primary display/cursor point plus `MonitorFromPoint/Rect` default semantics | NSScreen-backed Win32 monitor metrics, point/window/rect monitor lookup, monitor info, display enumeration, cursor point; Electron common screen binding now maps `getDisplayNearestPoint`/`getDisplayMatching` through cached display bounds instead of primary-display stubs; mac `libelectron.a` includes `_register_electron_common_screen`, and the Electron-mode executable registers the binding through `nodeModuleInitRegister()` | Yes, `screen-*` covers monitor metrics/enumeration/lookup, `MonitorFromRect`, nearest/default fallback, and clipped-empty enumeration; `screen-js-smoke` covers JS export shape and method delegation; `run_electron_mode_smoke.sh` checks linked-binding registration, controlled V8 runtime lookup/export availability, and real Node bootstrap `process._linkedBinding(...)` access; cursor point already used by menu/input paths | Add multi-monitor physical-device edge cases |
| nativeTheme | Theme/dark mode/high contrast | `SystemParametersInfoW` supports work area, animation, deterministic high contrast; JS `nativeTheme` exposes themeSource/read-only state, macOS system dark-mode detection, and prefers `electron_browser_native_theme` OS notification over fallback polling; Electron-mode binding source uses AppKit `effectiveAppearance`/`appearance` KVO; mac `libelectron.a` builds a minimal linked-binding archive containing `_register_electron_browser_native_theme`; mac `libnodejs.a` now supplies real Node bootstrap support plus the linked-binding bridge, `nodeModuleInitRegister()`, and `process._linkedBinding` runtime smoke path for this binding; `blink_build.js ... electron` pulls the nativeTheme registration object into the Electron-mode executable | Yes for automated path: `native-theme-*` covers deterministic native queries; `native-theme-js-smoke` covers JS export shape and fallback watcher behavior; `native-theme-native-notification-smoke` covers mocked no-polling binding; `electron-native-theme-appearance-smoke` drives real AppKit light/dark appearance changes through Electron-mode JS | Optional manual global OS appearance toggle E2E |
| powerMonitor | Suspend/resume/power events plus idle/battery state queries | Deterministic `GetSystemPowerStatus` shim for AC/battery status now uses macOS power-source data by default; idle APIs use existing Chromium path; macOS IOKit sleep/wake and power-source notifications are bridged into `WM_POWERBROADCAST`; `ApiPowerMonitor` creates a message window and registers the native bridge; mac `libelectron.a` includes `_register_electron_browser_powermonitor`, and the Electron-mode executable registers the binding through `nodeModuleInitRegister()` | Yes for injected path: `power-monitor-system-power-status-*` covers power status query; `power-monitor-native-notification-bridge` covers native dispatch into `WM_POWERBROADCAST`; `power-monitor-js-smoke` covers JS shape; `electron-power-monitor-event-smoke` verifies Electron-mode JS receives suspend/resume/on-battery/on-ac order | Optional real hardware sleep/wake event-order smoke |
| powerSaveBlocker | `start(type)`, `stop(id)`, `isStarted(id)` plus Win32 execution-state blocker semantics | JS blocker lifecycle aggregates to native `electron_browser_power_save_blocker.setExecutionState()`; that binding delegates to `SetThreadExecutionState`, which is backed by macOS IOPM assertions; mac `libelectron.a` includes `_register_electron_browser_power_save_blocker`, and the Electron-mode executable registers the binding through `nodeModuleInitRegister()` | Yes, `power-save-blocker-js-smoke` covers ID/type behavior; `power-save-blocker-*` covers execution-state plus IOPM assertion behavior; `electron-power-save-blocker-lifecycle-smoke` covers Electron-mode JS+native escalation/de-escalation | Add long-running leak/stress soak only if needed |
